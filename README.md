## Overview

**Week_05** is a C++ project structured around a modular build configuration using Premake and Raylib.

The project separates application code, third-party dependencies, generated build files, and compiled binaries into dedicated directories.

This organization makes the project easier to maintain, extend, and build across different configurations.

### Technologies

| Technology | Purpose |
| :--- | :--- |
| C++20 | Application programming language |
| Premake | Build configuration and project generation |
| Raylib | Graphics and windowing library |
| Visual Studio / MSVC | Example Windows development toolchain |
| Git | Version control |

## Project Structure

```text
Week_05/
│
├── Binaries/
│   ├── Intermediates/
│   │   └── windows-x86_64/
│   │       ├── Debug/
│   │       └── Release/
│   │
│   └── windows-x86_64/
│       ├── Debug/
│       └── Release/
│
├── build/
│   └── # Premake-generated project files
│
├── Docs/
│   └── render.gif
│
├── Game/
│   ├── include/
│   │   └── # Application header files
│   │
│   └── src/
│       └── # Application source files
│
├── Vendor/
│   └── raylib/
│       ├── src/
│       │   ├── external/
│       │   └── platforms/
│       │
│       └── Build-raylib.lua
│
├── .gitignore
├── Build.lua
└── README.md
```

### Directory Responsibilities

#### `Game/`

Contains the application's source code.

- `Game/src/` contains C++ implementation files (`.cpp`).
- `Game/include/` contains application header files (`.h`).

This separation keeps declarations and implementations organized.

#### `Vendor/`

Contains third-party dependencies.

Raylib is included directly in the repository rather than being downloaded during the build process.

The dependency is configured through its own Premake script:

`Vendor/raylib/Build-raylib.lua`

This allows Raylib to be built as a separate project and linked to the main application.

#### `Binaries/`

Contains generated compilation output.

The directory is organized by platform, architecture, configuration, and project name.

For example:

```text
Binaries/
├── Intermediates/
│   └── windows-x86_64/
│       └── Debug/
│           ├── Game/
│           └── Raylib/
│
└── windows-x86_64/
    └── Debug/
        ├── Game/
        └── Raylib/
```

- `Intermediates/` stores compiler-generated intermediate files.
- `windows-x86_64/` stores generated project outputs.
- `Debug/` and `Release/` separate build configurations.

This directory is generated during compilation and is not intended to be committed to version control.

#### `build/`

Contains the project files generated by Premake.

These files are generated from the root `Build.lua` configuration and should not be manually maintained.

#### `Docs/`

Contains project documentation and visual resources.

The demonstration GIF is expected to be located at:

`Docs/render.gif`

## Prerequisites

Before building the project, ensure that the following tools are installed.

### 1. C++ Compiler

A compiler with C++20 support is required.

For Windows, the recommended setup is:

- Microsoft Visual Studio 2022
- Desktop development with C++ workload
- MSVC C++ compiler
- Windows SDK

Other compatible C++20 toolchains may be used with an appropriate Premake action and configuration.

### 2. Premake

Install Premake 5 and ensure its executable is accessible through your system's PATH.

Verify the installation:

```bash
premake5 --version
```

If the command is not recognized, configure the PATH environment variable to include the directory containing the Premake executable.

Official website:

https://premake.github.io/

### 3. Raylib

Raylib is already included in the repository under:

```text
Vendor/raylib/
```

No separate Raylib installation should be necessary, provided the vendored source and its Premake build script are present.

Official website:

https://www.raylib.com/

## Building the Project

The project uses Premake to generate native project files and a C++ compiler to build the application.

The build configuration is maintained in:

```text
Build.lua
```

### Step 1: Clone the Repository

```bash
git clone <YOUR_REPOSITORY_URL>
```

Navigate into the project directory:

```bash
cd Week_05
```

Make sure the repository contains the Raylib dependency:

```text
Vendor/raylib/
```

### Step 2: Generate the Build Files

For Visual Studio 2022, execute the following command from the project root:

```bash
premake5 vs2022
```

This invokes Premake using the root `Build.lua` script and generates the Visual Studio solution and project files inside:

```text
build/
```

If you use another supported Premake action, replace `vs2022` with the corresponding action.

### Step 3: Open the Solution

Navigate to the generated `build/` directory and open the generated solution.

The workspace contains two projects:

- `Game`
- `Raylib`

The `Game` project is configured as the startup project.

### Step 4: Select a Build Configuration

The project supports two configurations:

| Configuration | Description |
| :--- | :--- |
| Debug | Development and debugging |
| Release | Optimized build |

The target architecture is:

```text
x86_64
```

Select the desired configuration and build the solution.

### Step 5: Run the Application

After a successful build, the output is organized according to the following pattern:

```text
Binaries/
└── <system>-<architecture>/
    └── <configuration>/
        └── <project-name>/
```

For the Windows x86_64 Debug configuration:

```text
Binaries/
└── windows-x86_64/
    └── Debug/
        └── Game/
```

The generated application executable should be located in the Game output directory.

## Build Configuration

The project is configured through Premake using the root `Build.lua` file.

The workspace is defined as:

```lua
local OutputDir = "%{cfg.system}-%{cfg.architecture}/%{cfg.buildcfg}"

workspace "Week_05"
    architecture "x86_64"
    configurations {"Debug", "Release"}
    startproject "Game"

    targetdir ("Binaries/" .. OutputDir .. "/%{prj.name}")
    objdir("Binaries/Intermediates/" .. OutputDir .. "/%{prj.name}")

    location "build"
```

### Workspace Configuration

| Property | Value |
| :--- | :--- |
| Workspace | `Week_05` |
| Architecture | `x86_64` |
| Configurations | Debug, Release |
| Startup project | Game |
| Generated project location | build |

### Game Project

The main application is defined as:

```lua
project "Game"
    kind "ConsoleApp"
    language "C++"
    cppdialect "C++20"
```

This configures the application as a C++20 console application.

The source files are collected from:

```lua
files {
    "Game/src/**.cpp",
    "Game/include/**.h"
}
```

The include directories are:

```lua
includedirs {
    "Vendor/raylib/src",
    "Game/include"
}
```

This allows the application to access both Raylib headers and its own project headers.

### Linking Raylib

The application links against the Raylib project:

```lua
links {"Raylib"}
```

On Windows, the following system libraries are also linked:

```lua
filter {"system:windows"}
    links {"opengl32", "gdi32", "winmm"}
```

Automatic linking is disabled:

```lua
implicitlink "Off"
```

This keeps the project's linking configuration explicit.

### Raylib Build Integration

The Raylib Premake configuration is included at the end of the root build script:

```lua
include "Vendor/raylib/Build-raylib.lua"
```

This allows Premake to configure the Raylib project alongside the Game project.

## Development Guidelines

To maintain a clean project structure, consider following these conventions.

### Source Files

Place application implementation files in:

```text
Game/src/
```

Use `.cpp` for C++ implementation files.

### Header Files

Place application declarations in:

```text
Game/include/
```

Use `.h` for header files, consistent with the current Premake file patterns.

### Third-Party Dependencies

Keep external libraries under:

```text
Vendor/
```

Avoid mixing third-party source files with application code.

### Documentation and Assets

Keep documentation, screenshots, and demonstration media under:

```text
Docs/
```

### Generated Files

Avoid manually editing files inside:

```text
Binaries/
build/
```

These directories are generated by the build process.

## Troubleshooting

### Premake command is not recognized

Ensure Premake 5 is installed and its executable is available through the system PATH.

Test with:

```bash
premake5 --version
```

### Raylib project cannot be found

Verify that the following file exists:

```text
Vendor/raylib/Build-raylib.lua
```

Also ensure the root `Build.lua` includes it correctly.

### Missing Raylib headers

Check that the following directory exists:

```text
Vendor/raylib/src/
```

The main Game project includes this directory through its Premake configuration.

### Linker errors involving Raylib

Verify that:

- Both Game and Raylib projects are included in the generated workspace.
- The Raylib project builds successfully.
- The Game project links against the correct Raylib project.
- The required platform-specific libraries are available.

### Build output is missing

Check the selected configuration and platform.

The expected output directory follows:

```text
Binaries/<system>-<architecture>/<configuration>/<project-name>/
```

Regenerate the project files if the Premake configuration has changed.
